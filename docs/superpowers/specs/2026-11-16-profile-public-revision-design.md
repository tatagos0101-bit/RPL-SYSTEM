# Member profile restrictions, photo removal and public preview

The user requests: member names cannot change after librarian registration; profile photos can be added/removed; the public landing-page catalog needs the same fixed-size book viewer and lower-slider removal already implemented for members. Implement directly within the existing React/FastAPI system. No new dependencies, schema, production access, account deletion or biometric policy.

## Name policy

The member Full Name field stays visible/read-only with a short librarian-managed explanation. Only phone/location remain in the Edit Profile form state and save payload. Keep email/password/photo controls and existing theme/layout. Server PUT /api/user/profile rejects a changed or null member name with403 before applying any other supplied change. An unchanged name may remain accepted for older clients that send it with phone/location. The database role is authoritative; forged role/verification payloads cannot bypass it. Existing librarian own-profile name edits remain unchanged; no new member-renaming endpoint is introduced. This policy does not invent a name-verification flag or modify signup.

## Photo controls and deletion

Reuse the existing avatar upload UI/helper and private storage rules. Add Add/Change photo wording and a Remove photo button when a photo exists. A shared in-flight guard disables competing upload/removal. Confirmed removal updates the profile and navigation to initials, publishes the existing same-tab/cross-tab profile revision, and allows a later fresh upload. Failures retain the prior displayed state with an accessible retry message. Do not persist a signed URL or avatar data in browser storage. Phone/location saves publish only those fields, avoiding stale whole-profile responses restoring a concurrently removed photo.

Add self-scoped DELETE /api/user/avatar with get_locked_current_user and lock_active_account. Use a small service beside existing identity-deletion helpers to reuse private-reference/category validation and the shared-reference guard. Never accept a client-supplied object URL/user identity as the deletion target. Repeated removal without a photo succeeds. Delete the private object through existing storage_service.delete_upload before clearing the database reference, following the established account-deletion retry convention. Provider/local deletion failure leaves the reference intact and returns a sanitized502. Legacy wrong-category/unsafe or shared references return409 without deleting. The endpoint commits NULL only after successful storage deletion. Storage cannot join the DB transaction: if a later commit fails, the original reference may point to an already deleted object; return an error and allow retry, rather than claiming success. No durable cleanup queue or retention duration is introduced.

## Public catalog viewer

Apply the proven member geometry to PublicBrowse only: viewport-bounded max48rem width and min(36rem,100dvh-2rem) height, fixed cover frame with existing BookCover/object-contain fallback, internally scrolling details, and Close outside the animated/scrolling content. Preserve public category/search/shelf/paging behavior and exact reserve/login links by role. Remove the lower slider/counter bar and its handlers; retain the cover index. Keep Previous/Next buttons visible at44px targets in a cover-region overlay, with matching desktop/landscape columns so short phone landscape avoids Close overlap. On phones, avoid duplicate availability labels colliding with navigation/index; the detail-panel status remains available. No change to availability or reservation rules.

## Verification

Backend red/green tests cover changed/null name denied atomically, unchanged name/phone/location allowed, staff own-name behavior, owner scoping, no-photo repeat, physical local deletion, mocked private cloud deletion, shared/invalid references, provider failure and DB-commit retry limits. Auth cases include anonymous, suspended, wrong session and must-change-password restrictions; preserve existing email/contact/session/upload/deletion suites. No real patron/photo/biometric fixtures or cloud writes.

Synthetic browser checks verify read-only names and outgoing payload, confirmed/error/retry removal, navigation and other-tab refresh, upload after removal, pending upload/removal exclusion, and mobile themes. Public viewer tests use missing/portrait/landscape/long descriptions across portrait/short landscape and enlarged text, with no slider, consistent size, accessible controls and unchanged login/reserve navigation. Run scoped lint/build/credential scan, source guards and focused fresh review. Confirm isolated local configuration with AUTO_MIGRATE=false before backend restart; leave localhost healthy. No commits/push/deployment.
