# Search and member catalog discovery

The user requests landing searches that open matching/highlighted catalog results, vertical desktop browsing while mobile shelves retain swipe behavior, and a member catalog matching the public walnut/amber shelves with recommendations, Trending, What's new, Books we love and genre sorting. The user chose existing member favorites for Books we love / Most loved. No ratings feature, external catalog data, new dependencies or schema change.

## Approach and scope

Reuse the existing React catalog shelf/card CSS and API helpers; add small shared category, literal-match highlight and sort controls. Use a server-side sort on the existing paginated public book list so every page is globally ordered. Client-only sorting of the current page is inadequate. A separate rating/editorial system is outside this request. Existing FastAPI authentication, recommendation algorithm, private files, member profile protections, copy identity, reservations/capacity, confirmation/recovery and modal dimensions remain intact. This is an authorized local implementation; no commit/push/deployment.

## Search

Landing submission routes to `/browse?q=<encoded trimmed title-or-author>` (empty to `/browse`), using a shared catalog path helper. Public catalog search reads/writes `q` with React Router search params, preserving browser back/forward and refresh. Keep typed spaces while editing; trim only the API query and highlight term, maximum200 characters. A result heading states the query; matching literal title/author substrings use semantic `mark` with accessible theme colors, never HTML injection or unescaped regex input. The server treats LIKE wildcard characters literally. No result auto-reserves or opens an unrelated detail.

## Sorting and data

Extend GET `/api/books` with validated sort `title`(existing default), `trending`, `newest`, `loved` and boolean `favorites_only`(defaultfalse). Apply search/category/availability first; server pagination/counts apply after optional positive favorite filtering. Trending ranks borrow_date within the last30days, including returned loans, then newest/id tie breaks and fills sparse activity with new titles. Newest uses library created_at, not publication year. Most loved ranks distinct favorite members who are active members with no deleted_at; no identity/counts need be exposed. Books we love requests loved+favorites_only=true so an unloved book is never described as loved. All ordering is deterministic before offset/limit. Existing default title/id and public response shape stay compatible. Reuse this listing for featured12-book resources and See all; do not sort or fetch the entire inventory in the browser.
