# Privacy and reporting release — November 6, 2026

Application release `ac85d64ee9bd` was fast-forwarded into `main`, pushed, and
promoted to both production Vercel projects after database recovery checks.
This release combines privacy-storage `0a4384b`, library-reporting `4f1ace9`,
and integration fixes preserving the fine-free circulation UI. PAD candidates
and unrelated working-tree changes were not included.

## Delivered

- Public Data Privacy page linked beside the landing-page copyright and from
  the entrance station; explicit camera start, pause, and hidden-page cleanup.
- AES-256-GCM storage for legacy face encodings, active/inactive embeddings,
  and spoof-alert snapshots. Production uses strict mode with an independent
  server-only keyring. Existing decrypted biometric values were preserved.
- Reporting center, dashboard, export workflows and copy acquisition records.
  The scoped migration added the acquisition table and reporting indexes,
  enabled RLS and retained restricted-runtime access without browser-role grants.
- QR circulation confirmation preserves return information without displaying
  estimated or final fines. Backend fine calculations were not removed.

## Release verification

- Prior combined-branch checks: 291 backend tests passed, 7 optional integration
  tests skipped; 83 frontend helper tests passed; build, lint and build secret scan
  passed. Browser checks covered privacy interactions and fine-free confirmation.
- Encrypted public-schema backups were restored into disposable, RAM-backed
  PostgreSQL 17 containers. Reporting and encryption migrations were run twice
  against the restored database, with record and decrypted-value preservation
  checks. Temporary containers were removed.
- Both live projects were paused and requests drained before the final backup,
  restore rehearsal and migration. Live audit found no remaining plaintext or
  old-key values in the three biometric columns; repeated encryption wrote no rows.
- Live synthetic-account checks passed: staff/member login, reporting through
  the restricted runtime account, wrong-role and suspended-session rejection,
  face-data deletion and logout revocation. Temporary accounts, embeddings and
  sessions were removed. These checks do not certify real-camera accuracy.
- Public health and anonymous-access checks passed. Desktop (1440px) and mobile
  (390px) browser checks verified the privacy link, page reload, entrance notice,
  camera staying off, and absence of page errors or horizontal overflow.

## Configuration and recovery

`DATABASE_URL` remained the restricted runtime credential. Three API Production
Sensitive variables configure biometric encryption; no key was placed in frontend
configuration or Git. The separate key recovery copy and encrypted database
backups are held in the restricted `F:/RPL-Backups` directory using Windows
CurrentUser DPAPI. Recovery depends on that Windows profile and its recovery
material; this is a local rollback copy, not an off-site disaster-recovery service.
The database backup covers the public application schema, not Storage objects or
Supabase-managed schemas. Do not deploy an older plaintext-only API against the
encrypted database. See [storage and recovery](BIOMETRIC_STORAGE.md).

The production environment had changed after the original release snapshot:
Supabase entries were refreshed and unused owner connection variables reappeared.
`POSTGRES_PASSWORD`, `POSTGRES_URL`, `POSTGRES_PRISMA_URL`, and
`POSTGRES_URL_NON_POOLING` were removed before building. Existing restricted
`DATABASE_URL`, authentication settings and current Supabase storage configuration
were preserved.

## Remaining limitations

- The notice does not implement consent capture, an approved retention schedule,
  or legal certification. Responsible-organization and privacy-contact policy
  decisions remain outstanding.
- PAD and physical-camera acceptance are separate work, unchanged by this release.
- The GitHub push reported 62 dependency alerts (31 high, 25 moderate, 6 low).
  Those alerts were not triaged in this release; this is not a clean dependency
  security audit or evidence that every alert affects production.
